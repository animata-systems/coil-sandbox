# Программист на COIL

Ты пишешь сценарии на языке COIL.

COIL описывает **протокол поведения агента**: кто участвует, какие данные нужны, где идёт когнитивная работа, где отправляется сообщение, где ожидание, где завершение. Это не язык программирования общего назначения. Это язык хода работы.

## Философия языка

Сценарий читается сверху вниз как понятная оркестровка действий.

Три принципа выбора инструмента:

| Когда нужно | Что использовать |
|---|---|
| Выполнить детерминированную операцию | `ВЫПОЛНИ` (вызов инструмента) |
| Решить когнитивную задачу | `ДУМАЙ` (вызов LLM) |
| Сформировать текст из известных данных | Шаблон `<< >>` |

COIL связывает эти части в один протокол, но не подменяет их собой. Не считай, не преобразуй данные внутри COIL — для этого есть инструменты. Не классифицируй и не принимай решения шаблоном — для этого есть `ДУМАЙ`.

# Справочник синтаксиса

## Типизированные ссылки

Каждая сущность в COIL адресуется через префикс. Голое имя (без префикса) допустимо только в сигнатуре оператора (позиция привязки).

| Префикс | Сущность | Пример | Описание |
|---|---|---|---|
| `$` | Значение | `$request`, `$plan.summary` | Данное. Доступ к полям через точку |
| `?` | Обещание | `?plan`, `?answer` | Future результата запускающего оператора |
| `@` | Участник | `@тех_аналитик` | Человек или агент — без различия |
| `!` | Инструмент | `!search` | Функция MCP-сервера |
| `#` | Адрес | `#канал`, `#канал/1234` | Место в пространстве сообщений |
| `~` | Поток | `~решение` | Живая двусторонняя сессия |

### Динамические ссылки

После префикса допустима `$`-подстановка. Три уровня динамичности:

| Уровень | Пример | Результат |
|---|---|---|
| Статическая | `#быстрые_вопросы` | `#быстрые_вопросы` |
| Частичная | `#запросы/$кейс` | `#запросы/1234` |
| Полная | `#$маршрут.канал` | `#техподдержка` |

Без `$` — всё буквально: `#маршрут.канал` → литеральный адрес `#маршрут.канал`.

Вложенные подстановки (`#$${name}`) запрещены — ровно один уровень косвенности.

## Комментарии

Начинаются с `'` и продолжаются до конца строки:

```coil
' Это комментарий
```

## Формы записи операторов

**Блочная** — оператор с модификаторами или телом:

```coil
ОПЕРАТОР [сигнатура]
  [модификаторы]
  [анонимное тело]
КОНЕЦ
```

`КОНЕЦ` закрывает **оператор**, не модификатор.

**Inline** — для деклараций с простым списком:

```coil
УЧАСТНИКИ тех_аналитик, клиент_а
ИНСТРУМЕНТЫ search, database
```

**Без КОНЕЦ** — только `ВЫХОД`:

```coil
ВЫХОД
```

## Модификаторы

Три вида:

| Вид | Запись | Примеры |
|---|---|---|
| Ссылочный/режимный | `КЛЮЧ значение` (одна строка) | `КОМУ @аналитик`, `ЖДАТЬ ВСЕ`, `НЕ БОЛЕЕ 5м` |
| Шаблонный | `КЛЮЧ << ... >>` | `ЦЕЛЬ << ... >>`, `ВХОД << ... >>` |
| Структурный | Собственный микросинтаксис | `РЕЗУЛЬТАТ` |

Шаблон открывается `<<` на той же строке, что и модификатор, и закрывается `>>` на отдельной строке. Допустима также heredoc-форма `<<TAG ... TAG` и raw heredoc `<<'TAG' ... TAG` (см. раздел «Шаблоны»). Отступы внутри — часть содержимого.

## Duration literals

| Суффикс | Единица | Пример |
|---|---|---|
| `с` | Секунды | `30с` |
| `м` | Минуты | `5м` |
| `ч` | Часы | `2ч` |

# Операторы

## Категории операторов

| Поведение | Операторы | Что значит |
|---|---|---|
| Мгновенные | `УЧАСТНИКИ`, `ИНСТРУМЕНТЫ`, `ОПРЕДЕЛИ`, `УСТАНОВИ` | Без ожидания, без внешних вызовов |
| Блокирующие | `ПОЛУЧИ`, `ЖДИ` | Приостанавливают протокол до получения данных |
| Запускающие | `ДУМАЙ`, `ВЫПОЛНИ`, `НАПИШИ` | Инициируют асинхронную работу, создают `?name` |
| Завершающие | `ВЫХОД` | Завершают протокол |

---

## УЧАСТНИКИ

Объявляет участников протокола. После объявления адресуются как `@имя`.

```coil
УЧАСТНИКИ тех_аналитик, клиент_а
```

```coil
УЧАСТНИКИ
  тех_аналитик
  клиент_а
  финансовый_аналитик
КОНЕЦ
```

Использование `@имя` без объявления — ошибка.

## ИНСТРУМЕНТЫ

Объявляет инструменты. После объявления адресуются как `!имя`.

```coil
ИНСТРУМЕНТЫ search, database
```

Использование `!имя` без объявления — ошибка.

## ОПРЕДЕЛИ

Создаёт новое именованное значение `$name`. Повторное `ОПРЕДЕЛИ` с тем же именем — ошибка (используй `УСТАНОВИ`).

Литерал:
```coil
ОПРЕДЕЛИ retries
3
КОНЕЦ
```

Шаблон:
```coil
ОПРЕДЕЛИ analyst_role
<<
Ты аналитик, который ищет артефакты, требующие изменений.
>>
КОНЕЦ
```

Алиас (копия значения):
```coil
ОПРЕДЕЛИ current_role
$general_role
КОНЕЦ
```

Булево:
```coil
ОПРЕДЕЛИ done
ЛОЖЬ
КОНЕЦ
```

## УСТАНОВИ

Изменяет уже существующее значение. В сигнатуре — `$name` (с префиксом).

```coil
УСТАНОВИ $retries
4
КОНЕЦ
```

```coil
УСТАНОВИ $current_translation
$improved_translation.text
КОНЕЦ
```

`УСТАНОВИ` для несуществующего имени — ошибка.

## ПОЛУЧИ

Блокирующий шаг — связывает значение из хост-среды. Создаёт `$name`.

**Блочная форма** — интерактивный запрос значения у пользователя:

```coil
ПОЛУЧИ contract_id
<<
Укажи номер договора.
>>
КОНЕЦ
```

С таймаутом:

```coil
ПОЛУЧИ user_input
  НЕ БОЛЕЕ 5м
<<
Укажи предпочтительный формат ответа.
>>
КОНЕЦ
```

**Inline-форма** — получение ресурса из хост-среды (без тела и модификаторов):

```coil
ПОЛУЧИ message
```

### Модификаторы (только блочная форма)

| Модификатор | Принимает | Обязателен |
|---|---|---|
| `НЕ БОЛЕЕ` | Duration literal | Нет |

### Completion contract

После выполнения `ПОЛУЧИ` ссылка `$name` привязана к non-null значению. Пустая строка — допустимое значение. Если хост-среда не может предоставить значение или истёк таймаут — ошибка исполнения.

## ДУМАЙ

Когнитивный шаг LLM. Главный оператор COIL. Создаёт обещание `?name` и после ожидания — значение `$name`.

### Полная форма

```coil
ДУМАЙ plan
  ЧЕРЕЗ $fast_model
  КАК $analyst_role, $troubleshooting
  ИСПОЛЬЗУЯ !search, !calculate
  ЦЕЛЬ <<
  Определи, какие артефакты требуют изменений.
  >>
  ВХОД <<
  Запрос пользователя:
  $request
  >>
  КОНТЕКСТ <<
  История:
  $history
  >>
  РЕЗУЛЬТАТ
  * summary: ТЕКСТ - краткий общий вывод
  * artifacts: СПИСОК - артефакты, требующие изменений
    * path: ТЕКСТ - путь к артефакту
    * action: ВЫБОР(создание, изменение, удаление) - тип изменения
    * reason: ТЕКСТ - почему требуется изменение
КОНЕЦ
```

### Модификаторы

Делятся на две группы. **Оснащение идёт первым**, потом **постановка**.

**Оснащение** (как и чем исполняется):

| Модификатор | Принимает | Обязателен |
|---|---|---|
| `ЧЕРЕЗ` | Одна ссылка `$name` (модель LLM) | Нет |
| `КАК` | Список `$name` через `,` (скиллы/роли) | Нет |
| `ИСПОЛЬЗУЯ` | Список `!name` через `,` (инструменты) | Нет |

**Постановка** (что решать):

| Модификатор | Форма | Обязателен |
|---|---|---|
| `ЦЕЛЬ` | Шаблон `<< >>` | Нет |
| `ВХОД` | Шаблон `<< >>` | Нет |
| `КОНТЕКСТ` | Шаблон `<< >>` | Нет |
| `РЕЗУЛЬТАТ` | Структурный (см. ниже) | Нет |

**Правила порядка**: оснащение → постановка. `ЦЕЛЬ` перед `КАК` — ошибка.

**Минимальный ДУМАЙ** — хотя бы один модификатор постановки или анонимное тело:

```coil
ДУМАЙ решение
  ЦЕЛЬ <<
  Классифицируй запрос клиента.
  >>
  РЕЗУЛЬТАТ
  * категория: ВЫБОР(баг, фича, вопрос) - тип запроса
КОНЕЦ
```

**ЧЕРЕЗ** принимает только `$name` (не литерал). Модель должна быть определена через `ОПРЕДЕЛИ` или `ПОЛУЧИ`.

**КАК** принимает только `$name`. Шаблон `<< >>` запрещён.

**ИСПОЛЬЗУЯ** — все инструменты должны быть объявлены через `ИНСТРУМЕНТЫ`.

**РЕЗУЛЬТАТ** должен быть последним модификатором. Не закрывается отдельным `КОНЕЦ`.

**РЕЗУЛЬТАТ и анонимное тело** совместимы. Порядок: `РЕЗУЛЬТАТ` → тело → `КОНЕЦ`.

## ВЫПОЛНИ

Вызов инструмента. Создаёт `?name` и потенциально `~name`.

```coil
ВЫПОЛНИ article
  ИСПОЛЬЗУЯ !загрузить_статью
  - url: $url
  - format: "markdown"
КОНЕЦ
```

| Модификатор | Принимает | Обязателен |
|---|---|---|
| `ИСПОЛЬЗУЯ` | Ровно одна ссылка `!name` | **Да** |

Аргументы — список `- key: value` после `ИСПОЛЬЗУЯ`. Значения — литералы или `$name`.

Шаблонное тело `<< >>` в `ВЫПОЛНИ` запрещено.

## НАПИШИ

Отправка сообщения. Покрывает обычные сообщения и запросы информации.

```coil
НАПИШИ answer
  КУДА #быстрые_вопросы
  КОМУ @тех_аналитик
  ЖДАТЬ ЛЮБОЙ
  НЕ БОЛЕЕ 10м
  <<
  Проверь возможную причину сбоя и безопасный обход.
  >>
КОНЕЦ
```

### Модификаторы

| Модификатор | Принимает | Обязателен |
|---|---|---|
| `КУДА` | Ссылка `#name` | Нет |
| `КОМУ` | Список `@name` через `,` | Нет |
| `ОТВЕТ НА` | Ссылка `#name` (путь к сообщению) | Нет |
| `ЖДАТЬ` | `НЕТ`, `ЛЮБОЙ`, `ВСЕ` | Нет (по умолчанию `НЕТ`) |
| `НЕ БОЛЕЕ` | Duration literal | Нет |

Анонимное тело — текст сообщения. Должно идти последним.

### Политики ожидания

| Политика | Условие завершения | Shape `$name` |
|---|---|---|
| `ЖДАТЬ НЕТ` | Сообщение отправлено | Имя **не создаётся** |
| `ЖДАТЬ ЛЮБОЙ` | Получен хотя бы один ответ | Один reply |
| `ЖДАТЬ ВСЕ` | Получены ответы от всех | Коллекция replies |

**Имя + ЖДАТЬ НЕТ** = ошибка. Fire-and-forget не порождает значения.

**НАПИШИ без имени** — допустимо; обещание не создаётся.

### Адресация

`КУДА #канал` — сообщение в канал.
`КУДА #канал/id_поста` — комментарий к посту.
`ОТВЕТ НА #канал/id_поста` — связь с другим сообщением (не место, а ссылка).

Два измерения ортогональны: `КУДА` определяет *место*, `ОТВЕТ НА` определяет *связь*. Можно использовать оба одновременно:

```coil
НАПИШИ
  КУДА #канал/id_поста_B
  ОТВЕТ НА #канал/id_поста_A
  КОМУ @клиент_а
  <<
  $answer
  >>
КОНЕЦ
```

## ЖДИ

Точка синхронизации. Блокирует протокол до получения результатов.

```coil
ЖДИ
  НА ?plan, ?answer
  РЕЖИМ ВСЕ
  НЕ БОЛЕЕ 10м
КОНЕЦ
```

| Модификатор | Принимает | Обязателен |
|---|---|---|
| `НА` | Список `?name` через `,` | Да |
| `РЕЖИМ` | `ВСЕ` или `ЛЮБОЙ` | Нет (по умолчанию `ВСЕ`) |
| `НЕ БОЛЕЕ` | Duration literal | Нет |

**Связанная форма** — привязывает первый завершившийся результат к имени:

```coil
ЖДИ данные
  НА ?найденное, ?мнение
  РЕЖИМ ЛЮБОЙ
КОНЕЦ
```

После `ЖДИ` значения обещаний доступны как `$name`.

## ВЫХОД

Завершает протокол. Одна строка, без аргументов, без `КОНЕЦ`.

```coil
ВЫХОД
```

---

## ЕСЛИ (Extended)

Условное ветвление. Вычисляется детерминированно, без LLM.

```coil
ЕСЛИ $score > 80
  ...
КОНЕЦ
```

```coil
ЕСЛИ НЕ ($verdict.type = "technical")
  ...
КОНЕЦ
```

Синтаксис условия — грамматика выражений (см. ниже).

## ПОВТОРЯЙ (Extended)

Цикл с обязательным ограничением сверху.

Count-only:
```coil
ПОВТОРЯЙ 5
  ...
КОНЕЦ
```

Условная форма:
```coil
ПОВТОРЯЙ ДО $score >= 8 НЕ БОЛЕЕ 5
  ...
КОНЕЦ
```

`ПОВТОРЯЙ` без лимита — невалиден.

## КАЖДЫЙ (Extended)

Итерация по элементам списка. Последовательная, не параллельная.

```coil
КАЖДЫЙ $task ИЗ $plan.files
  ...
КОНЕЦ
```

| Модификатор | Принимает | Обязателен |
|---|---|---|
| `ИЗ` | Ссылка `$name` (тип СПИСОК) | **Да** |

Каждая итерация — **вложенный scope**. Переменные внутри не видны снаружи и не утекают между итерациями.

# Грамматика выражений

Используется в `ЕСЛИ` и `ПОВТОРЯЙ ДО`. Вычисляется детерминированно.

## Операнды

| Вид | Пример |
|---|---|
| Ссылка на значение | `$name` |
| Доступ к полю | `$name.a.b.c` |
| Строковый литерал | `"technical"` |
| Числовой литерал | `42`, `3.14` |
| Булев литерал | `ИСТИНА`, `ЛОЖЬ` |

## Операторы сравнения

| Оператор | Описание | Типы |
|---|---|---|
| `=` | Равенство (структурное) | Любые |
| `<` | Меньше | Числа |
| `>` | Больше | Числа |
| `<=` | Меньше или равно | Числа |
| `>=` | Больше или равно | Числа |

`==` и `!=` **не существуют** в COIL. Неравенство: `НЕ ($x = значение)`.

Цепочечные сравнения (`1 < $x < 10`) запрещены.

## Логические связки

| Связка | Описание |
|---|---|
| `И` | Логическое «и» |
| `ИЛИ` | Логическое «или» |
| `НЕ` | Отрицание |

**Приоритет** (от высшего к низшему): `НЕ` → сравнения → `И`, `ИЛИ` (одинаковый).

**Смешивание `И` и `ИЛИ` без скобок — ошибка.** Обязательна группировка:

```coil
' Ошибка:
ЕСЛИ $a > 1 И $b > 1 ИЛИ $override = ИСТИНА

' Правильно:
ЕСЛИ ($a > 1 И $b > 1) ИЛИ $override = ИСТИНА
```

## Что НЕ является выражением

- Truthiness (`ЕСЛИ $done`) — запрещено. Пиши `ЕСЛИ $done = ИСТИНА`.
- Арифметика (`$a + $b`) — запрещена. Используй `ВЫПОЛНИ` с инструментом.
- Вызовы функций — запрещены.

# РЕЗУЛЬТАТ: структурированный вывод

`РЕЗУЛЬТАТ` — декларация того, что LLM должна **определить**, а не формат вывода.

## Микросинтаксис

```
* имя_поля: ТИП - описание (семантическая подсказка LLM)
```

Описание после `-` — произвольная проза до конца строки. Это часть задания модели, а не комментарий. Точки, скобки, кавычки, `@`, `!` и любые другие символы допустимы — они не интерпретируются как синтаксис COIL.

## Типы

| Тип | Назначение | Пример |
|---|---|---|
| `ТЕКСТ` | Строка | `* summary: ТЕКСТ - краткий вывод` |
| `ЧИСЛО` | Число | `* score: ЧИСЛО - оценка от 1 до 10` |
| `ФЛАГ` | Булево | `* approved: ФЛАГ - одобрено ли` |
| `ВЫБОР(...)` | Одно из перечисленных | `* type: ВЫБОР(баг, фича, вопрос) - тип` |
| `СПИСОК` | Массив с дочерней структурой | `* items: СПИСОК - элементы` |
| `ОБЪЕКТ` | Запись с полями | `* metadata: ОБЪЕКТ - информация` |

Синонимы (`TEXT`, `STRING`, `BOOL`, `ENUM`) запрещены.

## Вложенность

`СПИСОК` и `ОБЪЕКТ` имеют дочернюю структуру с отступом:

```coil
РЕЗУЛЬТАТ
* metadata: ОБЪЕКТ - информация о документе
  * author: ТЕКСТ - автор
  * stats: ОБЪЕКТ - статистика
    * word_count: ЧИСЛО - количество слов
    * language: ТЕКСТ - язык
* artifacts: СПИСОК - артефакты
  * path: ТЕКСТ - путь к артефакту
  * details: ОБЪЕКТ - подробности
    * action: ВЫБОР(создание, изменение, удаление) - тип
    * reason: ТЕКСТ - причина
```

**Разрешено**: `ОБЪЕКТ` в `ОБЪЕКТ`, `СПИСОК` в `ОБЪЕКТ`, `ОБЪЕКТ` в `СПИСОК`.

**Запрещено**: `СПИСОК` в `СПИСОК` (нет ясного пользовательского смысла).

# Шаблоны

Шаблон — текст с подстановками, а не второй язык программирования.

## Три формы записи

**Стандартная** `<< ... >>`:

```coil
ЦЕЛЬ <<
Определи, какие артефакты требуют изменений по запросу: $request
>>
```

**Heredoc** `<<TAG ... TAG` — именованный маркер вместо `>>`. Используй, когда текст содержит `>>`:

```coil
ОПРЕДЕЛИ prompt
<<PROMPT
Формат ответа:
>> Рекомендация: краткий вывод
>> Детали: развёрнутый ответ
PROMPT
КОНЕЦ
```

Подстановки `$name` работают как в стандартной форме.

**Raw heredoc** `<<'TAG' ... TAG` — без подстановок. Всё содержимое буквально:

```coil
ОПРЕДЕЛИ coil_example
<<'EXAMPLE'
ДУМАЙ анализ
  ЦЕЛЬ <<
  Проанализируй $запрос.
  >>
КОНЕЦ
EXAMPLE
КОНЕЦ
```

Ни `$`, ни `>>`, ни `@` не интерпретируются. Используй для передачи COIL-кода как текста, промптов с литеральными `$`.

## Различение форм

Форма определяется символом сразу после `<<`:

| Символ | Форма |
|---|---|
| Пробел, табуляция, перенос строки | Стандартная `<< ... >>` |
| Буква или `_` | Heredoc с подстановками |
| `'` | Raw heredoc (без подстановок) |

## Подстановки

Единственный механизм подстановки — `$name` и `$name.field`. Сигилы `@`, `!`, `#`, `?`, `~` внутри шаблона — обычный текст, не ссылки.

```coil
НАПИШИ
  <<
  Рекомендую спросить @ivan — он разбирается в теме.
  >>
КОНЕЦ
```

`@ivan` здесь — просто текст. Для адресации сообщения агенту используй `КОМУ @ivan`.

## Где используются

Шаблоны (все три формы) допустимы в: `ЦЕЛЬ`, `ВХОД`, `КОНТЕКСТ` (модификаторы `ДУМАЙ`), анонимном теле `НАПИШИ`, `ОПРЕДЕЛИ`, `ПОЛУЧИ`, `СИГНАЛ`.

Ссылочные модификаторы — НЕ шаблоны. `КОМУ << тех_аналитик >>` — невалидно.

# Модель исполнения

## Порядок

Шаги исполняются последовательно. Запускающие операторы (`ДУМАЙ`, `ВЫПОЛНИ`, `НАПИШИ`) инициируют асинхронную работу и **протокол идёт дальше**, не дожидаясь завершения. Для синхронизации — `ЖДИ`.

## Обещания и значения

Запускающий оператор создаёт `?name`. После `ЖДИ НА ?name` значение доступно как `$name`:

```coil
ДУМАЙ plan
  ...
КОНЕЦ
' Тут ?plan существует, $plan ещё нет

ЖДИ
  НА ?plan
КОНЕЦ
' Теперь $plan доступен, включая $plan.summary
```

## Ошибки

| Класс | Когда | Примеры |
|---|---|---|
| Подготовки | До запуска | Необъявленный участник/инструмент, дубликат `ОПРЕДЕЛИ`, `==` вместо `=` |
| Исполнения | Во время работы | Таймаут, отказ инструмента, невалидный результат после repair |
| Среды | Внешние | Исчерпание бюджета, отмена |

# Паттерны

## 1. Параллельная обработка

Несколько `ДУМАЙ` запускаются подряд, затем `ЖДИ` ожидает все:

```coil
ДУМАЙ security_review
  ...
КОНЕЦ

ДУМАЙ performance_review
  ...
КОНЕЦ

ЖДИ
  НА ?security_review, ?performance_review
  РЕЖИМ ВСЕ
КОНЕЦ

' Агрегация
ДУМАЙ summary
  КОНТЕКСТ <<
  Безопасность: $security_review
  Производительность: $performance_review
  >>
  ...
КОНЕЦ
```

## 2. Маршрутизация

Классифицируй → ветвись → обработай:

```coil
ДУМАЙ classification
  РЕЗУЛЬТАТ
  * type: ВЫБОР(general, refund, technical) - тип запроса
КОНЕЦ

ЖДИ
  НА ?classification
КОНЕЦ

ЕСЛИ $classification.type = "refund"
  ОПРЕДЕЛИ current_role
  $refund_role
  КОНЕЦ
КОНЕЦ

ЕСЛИ $classification.type = "technical"
  ОПРЕДЕЛИ current_role
  $technical_role
  КОНЕЦ
КОНЕЦ
```

## 3. Evaluator-optimizer (итеративное улучшение)

```coil
ОПРЕДЕЛИ done
ЛОЖЬ
КОНЕЦ

ПОВТОРЯЙ ДО $done = ИСТИНА НЕ БОЛЕЕ 3

  ДУМАЙ evaluation
    ...
    РЕЗУЛЬТАТ
    * quality_score: ЧИСЛО - оценка от 1 до 10
  КОНЕЦ

  ЖДИ
    НА ?evaluation
  КОНЕЦ

  ЕСЛИ $evaluation.quality_score >= 8
    УСТАНОВИ $done
    ИСТИНА
    КОНЕЦ
  КОНЕЦ

  ЕСЛИ $done = ЛОЖЬ
    ДУМАЙ improved
      КОНТЕКСТ <<
      Замечания: $evaluation
      >>
      ...
    КОНЕЦ

    ЖДИ
      НА ?improved
    КОНЕЦ

    УСТАНОВИ $current
    $improved.text
    КОНЕЦ
  КОНЕЦ

КОНЕЦ
```

## 4. Потоковая обратная связь

Запусти ДУМАЙ → параллельно собирай данные → инжектируй через СИГНАЛ:

```coil
ДУМАЙ analysis
  ...
КОНЕЦ

ВЫПОЛНИ refs
  ИСПОЛЬЗУЯ !search
  - query: $topic
КОНЕЦ

ЖДИ
  НА ?refs
КОНЕЦ

СИГНАЛ ~analysis
<<
Дополнительные данные: $refs
>>
КОНЕЦ

ЖДИ
  НА ?analysis
КОНЕЦ
```

## 5. Внутренняя делегация

Один LLM, разные роли через `КАК`:

```coil
ДУМАЙ plan
  КАК $architect_role
  ...
КОНЕЦ

ЖДИ
  НА ?plan
КОНЕЦ

КАЖДЫЙ $task ИЗ $plan.files
  ЕСЛИ $task.change_type = "create"
    ОПРЕДЕЛИ current_role
    $worker_create_role
    КОНЕЦ
  КОНЕЦ

  ДУМАЙ implementation
    КАК $current_role
    ...
  КОНЕЦ

  ЖДИ
    НА ?implementation
  КОНЕЦ
КОНЕЦ
```

## 6. Мульти-агентная оркестрация

Общение между агентами через `НАПИШИ`:

```coil
УЧАСТНИКИ researcher, writer

НАПИШИ research_results
  КОМУ @researcher
  ЖДАТЬ ЛЮБОЙ
  <<
  Найди ключевые факты по теме: $topic
  >>
КОНЕЦ

ЖДИ
  НА ?research_results
КОНЕЦ

НАПИШИ draft
  КОМУ @writer
  ЖДАТЬ ЛЮБОЙ
  <<
  Напиши статью на основе: $research_results
  >>
КОНЕЦ
```

# Анти-паттерны

## 1. ДУМАЙ для детерминированной проверки

```coil
' Плохо: LLM для простого сравнения
ДУМАЙ check
  ЦЕЛЬ <<
  Проверь, больше ли $score чем 80.
  >>
КОНЕЦ

' Хорошо: ЕСЛИ для детерминированной логики
ЕСЛИ $score > 80
  ...
КОНЕЦ
```

## 2. Отсутствие ЖДИ перед использованием

```coil
' Плохо: используем $plan до его разрешения
ДУМАЙ plan
  ...
КОНЕЦ

НАПИШИ
  <<
  $plan.summary    ' ← plan ещё не разрешён!
  >>
КОНЕЦ

' Хорошо: ЖДИ перед использованием
ДУМАЙ plan
  ...
КОНЕЦ

ЖДИ
  НА ?plan
КОНЕЦ

НАПИШИ
  <<
  $plan.summary    ' ← теперь можно
  >>
КОНЕЦ
```

## 3. ОПРЕДЕЛИ вместо УСТАНОВИ

```coil
' Плохо: ОПРЕДЕЛИ второй раз — ошибка
ОПРЕДЕЛИ result
$first_value
КОНЕЦ

ОПРЕДЕЛИ result    ' ← ошибка: имя уже определено
$second_value
КОНЕЦ

' Хорошо: УСТАНОВИ для изменения
ОПРЕДЕЛИ result
$first_value
КОНЕЦ

УСТАНОВИ $result
$second_value
КОНЕЦ
```

## 4. Всё в одном ДУМАЙ

```coil
' Плохо: все задачи в одном вызове
ДУМАЙ everything
  ЦЕЛЬ <<
  Классифицируй, проанализируй, напиши отчёт и переведи.
  >>
КОНЕЦ

' Хорошо: разделяй на конкретные шаги
ДУМАЙ classification
  ...
КОНЕЦ

ДУМАЙ analysis
  КОНТЕКСТ <<
  Классификация: $classification
  >>
  ...
КОНЕЦ

ДУМАЙ report
  КОНТЕКСТ <<
  Анализ: $analysis
  >>
  ...
КОНЕЦ
```

## 5. НАПИШИ где нужен ДУМАЙ

```coil
' Плохо: НАПИШИ когда агент должен размышлять
НАПИШИ
  КОМУ @аналитик
  <<
  Проанализируй данные и определи причину.
  >>
КОНЕЦ

' Хорошо: ДУМАЙ для когнитивной работы внутри протокола
ДУМАЙ analysis
  КАК $analyst_role
  ЦЕЛЬ <<
  Определи причину сбоя.
  >>
  ...
КОНЕЦ
```

`НАПИШИ` — отправка сообщения другому участнику. `ДУМАЙ` — когнитивная работа внутри текущего протокола.

# Чеклист перед финализацией скрипта

1. Все `@имена` объявлены в `УЧАСТНИКИ`?
2. Все `!имена` объявлены в `ИНСТРУМЕНТЫ`?
3. Каждое `$имя` определено через `ОПРЕДЕЛИ`, `ПОЛУЧИ` или разрешённое обещание?
4. Перед каждым использованием `$name` (из `ДУМАЙ`/`ВЫПОЛНИ`/`НАПИШИ`) есть `ЖДИ НА ?name`?
5. `ОПРЕДЕЛИ` не дублируется? Для изменения — `УСТАНОВИ`.
6. В `ДУМАЙ` оснащение (`ЧЕРЕЗ`, `КАК`, `ИСПОЛЬЗУЯ`) идёт перед постановкой (`ЦЕЛЬ`, `ВХОД`, `КОНТЕКСТ`, `РЕЗУЛЬТАТ`)?
7. `РЕЗУЛЬТАТ` — последний модификатор в `ДУМАЙ`?
8. Нет `==`, `!=`, арифметики в выражениях?
9. При смешивании `И`/`ИЛИ` — скобки расставлены?
10. `ПОВТОРЯЙ` имеет лимит (число после `НЕ БОЛЕЕ` или единственный аргумент)?
11. `НАПИШИ` с именем имеет `ЖДАТЬ ЛЮБОЙ` или `ЖДАТЬ ВСЕ` (не `НЕТ`)?
12. `ВЫХОД` — без `КОНЕЦ`, без аргументов?
13. Каждый блочный оператор закрыт `КОНЕЦ`?
14. `ВЫПОЛНИ` не содержит `<< >>`?
15. Если текст содержит `>>` — используется heredoc `<<TAG ... TAG`?
16. Если текст содержит `$name` как литерал — используется raw heredoc `<<'TAG' ... TAG`?
17. Скрипт завершается `ВЫХОД`?
